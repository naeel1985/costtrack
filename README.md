# Cashflow — Forward-looking personal finance

A single-user, local-first personal finance tracker built around one idea most
apps ignore: **not just what you spent, but whether your accounts will hold
enough money when future obligations hit** — especially post-dated cheques
(PDCs), which are a fact of life in the UAE.

Default currency is **AED**; multi-currency is supported via a manually-editable
rate table (no external API).

---

## The three pillars

1. **Income** — recurring (salary) and one-off (freelance, reimbursements,
   gifts) across multiple accounts.
2. **Costs** — daily expenses with categories, plus recurring costs (rent,
   subscriptions, loan installments).
3. **Future provisions & PDC tracking** — the differentiator. Issue/receive
   post-dated cheques and set aside provisions for known costs; the app projects
   account balances forward and **warns when a cheque is likely to bounce** or a
   provision is underfunded.

## Quick start

```bash
npm install
npm run db:migrate      # create the SQLite schema (prisma/dev.db)
npm run db:seed         # realistic AED sample data
npm run dev             # http://localhost:3000
```

Already migrated and just want fresh sample data:

```bash
npm run db:reset        # drops, re-migrates, and re-seeds
```

## How the projection logic works

The projection engine lives in [`src/lib/projection.ts`](src/lib/projection.ts)
and is deliberately **pure** — it imports nothing from Prisma or Next, so it is
fully unit-tested in isolation ([`src/lib/projection.test.ts`](src/lib/projection.test.ts)).

1. **Starting point.** For each account, the *current* balance is computed from
   its opening balance plus every **posted** ledger transaction up to today
   ([`src/server/balances.ts`](src/server/balances.ts)). No stale stored
   balances.
2. **Future events.** Three sources are expanded into signed, dated events over
   the horizon (30 / 60 / 90 days):
   - **Recurring rules** → occurrences generated by `expandRecurrence`
     (respecting interval, end date, and occurrence count).
   - **Pending PDCs** → an outflow (issued) or inflow (received) on the cheque's
     clearing date.
   - **Scheduled transactions** and **what-if** scenarios.
3. **Day-by-day fold.** `projectBalances` walks each day, applies that day's
   events, and records the running balance per account plus the combined total.
4. **Warnings.** It flags:
   - **PDC bounce** — an issued cheque whose clearing day leaves the account
     negative → *"Cheque #204 for 5,000 AED may bounce on 15 Aug — projected
     balance −1,800 AED"*.
   - **Negative balance** — first day any account goes below zero.
   - **Buffer breach** — first day an account drops below its user-set safety
     buffer.
5. **Runway.** `computeRunway` estimates how many months current balances last
   at the recent average monthly net cash flow.

Everything is in **integer minor units** (fils/cents). There is no floating
point arithmetic anywhere in the ledger or projection — see
[`src/lib/money.ts`](src/lib/money.ts). Money is only converted to a decimal at
the very edge for display or input parsing.

### Clearing a cheque

Marking a PDC **cleared** creates a matching ledger `Transaction` and links it
back to the cheque, so the register and the ledger stay reconciled. Reopening or
deleting the cheque unwinds that transaction.

## Feature tour

- **Dashboard** — net position, month income/spend, savings rate, cash runway,
  the interactive **projected-balance chart** (30/60/90 + **what-if simulator**),
  upcoming-obligations feed, and bounce/buffer warnings.
- **Income / Costs** — fast quick-add (`N` or `⌘K`), filtering, inline
  edit/delete, and recurring rules with a live occurrence preview.
- **Cheques (PDCs)** — table **and** calendar view, filters, one-click
  clear/bounce, 7-day clearing alerts, and **batch creation** (e.g. 12 monthly
  rent cheques, optionally spawning a recurring rule).
- **Provisions** — sinking funds with progress bars, on-track/behind vs due
  date, and a suggested monthly set-aside.
- **Reports** — income-vs-spending trend, category donut, top merchants, and
  full **CSV/JSON import & export**.
- **Cross-cutting** — global `⌘K` command palette, multi-currency rate table,
  dark mode, mobile-first responsive layout (daily phone use is first-class).

See [DECISIONS.md](DECISIONS.md) for the design rationale and trade-offs.

## Data model

`Account`, `Category`, `Transaction` (unified ledger: income / expense /
transfer), `RecurringRule`, `PDC`, `Provision` + `ProvisionAllocation`,
`Budget`, `ExchangeRate`, `AppSetting`. Schema:
[`prisma/schema.prisma`](prisma/schema.prisma).
